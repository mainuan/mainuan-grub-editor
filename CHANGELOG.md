## [2.0.2-8] - 2026-08-01

### ✨ Added
- New "Default Boot Mode" selector in General settings, with three explicit choices: a fixed entry, the last installed kernel, or the last booted kernel. Until now GRUB's three possible behaviours could only be reached by editing `/etc/default/grub` by hand.
- The boot entry selector is greyed out unless "Fixed entry" is chosen, since in the other two modes GRUB picks the entry itself and any value shown there would be ignored.

### 🐛 Fixed
- Applying changes in General settings pinned the boot entry to the current kernel, even when the boot entry dropdown had never been touched. `GRUB_DEFAULT` was rewritten with the literal menu entry title on every save, so a newly installed kernel was never booted after a reboot. The stored value is now left untouched unless the user actually selects a different entry.

## [2.0.2-7] - 2026-07-29

### 🐛 Fixed
- Screen resolution was written to `/etc/default/grub` using its translated label instead of its actual value. On a German system this produced `GRUB_GFXMODE=automatisch`, which GRUB does not understand. The combo now keeps the raw value separate from the text shown to the user.
- Custom entries created with "Add entry" could not be removed: the Boot Entries tab classified them as kernel entries and refused, claiming they belonged to an installed kernel. They can now be enabled, disabled and deleted, with a confirmation prompt before removal.
- Disabled custom entries stay visible in the list instead of vanishing from the tab, so they can be re-enabled or deleted later — same behaviour memtest entries already had.
- The launcher wrapper registered the window under `com.mainuan.grubeditor` while the desktop file declares `org.mainuan.grubeditor`, so the window did not associate with its launcher in the taskbar and could show a generic icon.

---

## [2.0.2-6] - 2026-07-23

### 🐛 Fixed
- Boot entries parser no longer lists duplicate memtest entries generated by GRUB's `pc`/`efi` platform conditionals.
- Boot entry type label now correctly recognizes "Memory test" titles instead of falling back to "system".
- Fixed a broken regex that prevented the boot entry path column from ever showing a value.

### ✨ Added
- Memtest entries in the Boot Entries tab can now be disabled (commented out) or permanently removed (binary deleted from `/boot`) for real, instead of only updating the on-screen list.
- Disabled memtest entries stay visible (dimmed) in the list so they can be re-enabled or deleted later.
- Boot Entries tab now shows the real kernel/binary path loaded by each entry.
- "Add entry" now writes a real custom `menuentry` block to `/etc/grub.d/40_custom` instead of doing nothing.

### 🔧 Changed
- Recovery-mode and other-OS entries are no longer listed in the Boot Entries tab, since they're already managed as a category in "General settings" — avoids a second, redundant control for the same GRUB switch.
- Kernel/OS entries in the Boot Entries tab now show a specific explanation instead of a generic "not supported" message.

## Legacy 1.x — Prior to Unification

Before version 2.0.0, the project existed as two separate branches:

- **Tyron** (XFCE + X11): versions 1.0.0 – 1.0.9, released April–August 2025
- **Tyson** (Plasma 6 + Wayland): versions 1.0.0 – 1.0.5, released May–July 2025

Both branches were merged and unified into version 2.0.0 (January 2026).

## Contribute

To report bugs or request features:
- **Issues**: https://github.com/MainuanLinux/mainuan-grub-editor/issues
- **Discussions**: https://github.com/MainuanLinux/mainuan-grub-editor/discussions
- **Email**: info@mainuanlinux.com

To contribute translations:
1. Create file `translations/locales/XX.py` (XX = language code)
2. Copy structure from `translations/locales/en.py`
3. Translate all `STRINGS`
4. Add language to `SUPPORTED_LANGUAGES` in `strings.py`
5. Submit Pull Request
